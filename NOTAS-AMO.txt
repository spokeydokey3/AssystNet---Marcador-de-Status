AssystNet Status Tagger — Firefox 3.8.4 review notes

Purpose: local ticket tags and independent operator-maintained contact checkboxes on
http://cati.tj.ce.gov.br/assystnet/ and https://cati.tjce.jus.br/assystnet/.
No official ticket status is changed. No telemetry, remote code, independent private API
requests or third-party transmission. Data uses browser.storage.local only. Permissions
remain storage/downloads and the two declared hosts. Firefox identity is preserved:
assyst-status-tagger@tjce.local.

Changes in 3.8.4:
- At the user's request, automatic native refresh no longer pauses for text/row selection.
  The selection API and row-selection checks/messages were removed from autoRefresh.js.
- Focused checkbox/radio and action buttons are not mistaken for editable text fields.
- Editable fields, open menus/dialogs, tag/contact writes, native loading and queue scans
  still defer refresh. Selection is never cleared by the extension to permit a click.
  The native AssystNet refresh may recreate the grid and reset selection.
- No storage/schema/backup-format/permission changes. Popup keeps tags, JSON backup, CSV
  report, cleanup and optional native refresh in that order.

Native refresh is disabled by default, interval 60 seconds (choices 30/60/120/300).
Background tabs are opt-in. It clicks one uniquely associated native Dijit valueNode input
from the supplied markup, or the original visible button when that input is not identified.
It does not invoke page objects/private handlers, reload the page or send keyboard shortcuts.
Targets: #eventMonitor/4 own queue, or the unique #homepage panel headed
“Chamados Atribuídos a mim”. No generated Dojo IDs are used. The existing MutationObserver
handles native loading/style/grid signals; no additional observer is installed. A single
watchdog prevents overlapping refreshes, and unknown completion stops repeated clicks.
Read-only status shows pause reasons and page-session automatic-attempt/completion counters.
Counters are in memory only; observed UI completion does not prove server success.

Tags begin empty on new profiles. Explicit existing definitions and legacy assignments are
preserved. Four contact checkboxes toggle independently, without date/holiday/response locks.
Dates and the seven-day reference are informational; no automatic ticket closure is performed.
Storage/JSON remain schema/format 3. Legacy JSON formats are accepted; v3 requires Firefox
or Chrome 3.6.0+. Unknown future schemas are rejected without rewriting their data.

Automatic cleanup is enabled by default for the complete own queue in the full monitor or
uniquely scoped homepage panel. It rejects detected filters/loading, ambiguous/incomplete
grids, changed contexts and disagreements between two complete virtual-grid reads. Final
context is rechecked before committing. Only absent ticket assignments/contacts are removed;
tag definitions remain. A recovery copy and the cleanup commit in one write. Empty queues
require manual confirmation before wiping marks; their verified report can still be empty.
Restore preserves subsequent edits, pauses cleanup and invalidates saved report membership.
Selection-related safeguards of destructive cleanup are unchanged by this update.

CSV uses open references from the latest verified queue, including untagged tickets, with
current marks. Timestamp is disclosed in the popup and filename. Once saved it downloads
without an AssystNet tab; server changes require another queue scan. With no saved queue,
CSV scans the visible own queue. Import and cleanup undo invalidate saved membership.
Normal JSON transfers tags/contacts, not computer-local queue snapshots or preferences.

Build: ten readable runtime files; no framework, bundler, transpiler, minifier or external
runtime library. Shared source ZIP includes build.py and CONSTRUIR.md. Python 3.12+:
  python3 build.py --browser firefox
Output: releases/AssystNet-3.8.4-submissao.zip. Tested with Linux/Python 3.12.14.
No npm or network is required to build. Runtime bytes are copied unchanged with fixed ZIP
metadata; REPRODUCAO.txt records SHA-256. Chrome adapters are excluded from Firefox ZIP.
Source-to-submission reproduction is checked byte for byte.

Validation: 72 Node tests, 36 simulated-DOM scenarios, eight Chromium UI/Blob/refresh cases
with simulated extension APIs/server; web-ext 10.8.0 lint with zero errors/warnings/notices.
The regression keeps actual text/row selection and focused checked selectors while refresh
completes twice on both hosts/views. No authenticated institutional session was accessed.
Real Ajax/Dojo behavior, filter preservation and both deployments need operator validation.
No credentials, real operational backups or ticket details are included in this submission.
