AssystNet Status Tagger — Firefox 3.8.3 review notes

Purpose: local ticket tags and operator-maintained contact checkboxes on the two
AssystNet hosts declared in the manifest. No official ticket status is changed.
No independent AssystNet requests, telemetry, remote code or third-party data transmission. The optional refresh clicks the native application control, whose own requests use the existing session.
Permissions remain storage and downloads. Data uses browser.storage.local only.
The existing Firefox ID assyst-status-tagger@tjce.local is preserved.

The ten runtime files are readable JavaScript, HTML and CSS. No framework,
bundler, transpiler, minifier or external runtime library is used. Source ZIP includes
build.py, requirements and full step-by-step instructions in CONSTRUIR.md.
With Python 3.12+ run: python3 build.py --browser firefox
The output is releases/AssystNet-3.8.3-submissao.zip. Tested on Linux/Python 3.12.14.
No npm dependencies or network access are required to build. The script copies the
Firefox runtime bytes unchanged, with fixed ZIP metadata; REPRODUCAO.txt records
the SHA-256. Source-to-submission reproduction was checked byte for byte.
Chrome adapters in the shared source archive are excluded from the Firefox ZIP.

Changes:
- Detail controls match the complete #events/ reference to a visible breadcrumb,
  irrespective of breadcrumb position. Stale controls cannot edit a different ticket.
- Four independent checkboxes can toggle freely, without a confirmation dialog.
  Dates are marking dates, not evidence of actual contact. Calendar-day information
  and the seven-day reference are informational; no date, holiday or response lock.
- Storage schema 3 and JSON format 3 retain independent checkbox positions.
  Legacy formats and dates migrate without dropping tag assignments. Unknown future
  schemas are rejected without rewriting their data. Older clients cannot import v3.
- Automatic cleanup is enabled by default for the observed own-queue route
  #eventMonitor/4 or the uniquely scoped own panel on #homepage. It refuses detected filters, loading, ambiguous/incomplete grids,
  other routes and changed contexts. It compares two complete virtual-grid captures,
  validates full membership and rechecks context before committing. Only absent
  ticket tag assignments and contact records are removed; tag definitions remain.
  Empty queues never wipe records automatically and require explicit manual confirmation.
  A single recovery checkpoint and the new state are committed in one storage write.
  Restore preserves subsequent edits and pauses automatic cleanup. No history cleanup
  is performed from individual ticket pages or partial visible rows.
- CSV uses a persisted verified open-queue list with current marks. The popup and filename
  disclose its timestamp; subsequent server changes require a new scan. Once saved, downloads
  work without an AssystNet tab. With no saved list, CSV scans the visible own queue. Importing
  JSON or undoing cleanup invalidates this computer-local list; it is excluded from JSON.
- New profiles have no preset tags. Explicit existing definitions and legacy referenced
  assignments are preserved. No migration removes user tags.

Testing: 72 automated Node tests (including four Chrome/Firefox portability tests), thirty-five simulated-DOM scenarios and eight Chromium
interface/Blob checks with simulated extension APIs passed. Firefox ZIP web-ext
10.8.0 lint: zero errors, warnings and notices. Firefox/live institutional integration
must still be tested by an authorized operator. Filter detection depends on the host DOM.

Suggested review: create a tag, open a ticket from different entry points, toggle
nonconsecutive boxes, transfer JSON, and check own-queue cleanup/recovery using synthetic
data. Live institutional access may require an authorized account. No credentials,
operational backups or real ticket details are included in the submission.


The optional autoRefresh.js introduced in 3.7.0 is retained in 3.8.3. It is disabled by default; interval defaults to
60 seconds, with choices 30/60/120/300 seconds. Background tabs are opt-in. A single
controller timeout is canceled/rescheduled on settings, visibility and navigation.
It clicks the supplied native eventMonitorRefreshButton on #eventMonitor/4, or the
refresh control within the unique homepage titlebar headed “Chamados Atribuídos a mim”
on #homepage. Generated Dojo IDs are not used. It never reloads the page.
It reuses the existing MutationObserver and yields to editing, selection, tag writes,
dialogs and queue scans. It observes native loading/grid signals, not presumed Ajax
success; unknown completion pauses repeated clicks and protects cleanup. See
AUTO_REFRESH.md for operator tests of real native behavior and filter preservation.
No permissions added. Preferences use local storage and are not part of ticket backups.
Ticket JSON remains format 3, compatible with Firefox/Chrome 3.6.0.

The inherited 3.8.1 protections fix offscreen parked Dojo wrappers and
recognizes the public DojoX Standby underlay's display/opacity loading animation even
when grid data remains unchanged. The watchdog no longer restarts on every mutation.
Manual native refresh also guards scans when auto-clicking is disabled; an interrupted
scan aborts without restoring scroll during native loading or deleting data. The existing
observer additionally watches style/hidden, without rescanning the grid for animation styles.
A read-only status request from the popup reports waiting/pause/loading reasons in its
source tab and recommends reloading the tab after an extension update when code is missing.
No new permissions, external libraries, private page API calls or data format changes.
Dojo markup is modeled from public upstream source; institutional integration is still
unverified. The actual host loading-indicator DOM and deployed Dojo version are unknown.

The inherited 3.8.2 protections narrow interaction detection. Ordinary boolean checkboxes, empty popup
wrappers and permanent unfocused/unexpanded listboxes are no longer treated as selections.
Rows/selector inputs must belong to a reference-bearing grid in the own-queue panel;
explicit aria-selected=false and selection classes on ordinary cells are ignored.
Text selection must intersect the own panel and remain rendered/visible. Its text is
checked locally for emptiness only, never stored, logged or transmitted. Menus need visible
items and popup/focus/expanded-controller evidence; dialogs need rendered visible content
or an explicit modal signal. Offscreen/transparent dialogs and hidden SPA selections do
not pause refresh. The popup reports distinct text/row/menu/dialog pause reasons.
Genuine selection still prevents clicks; the extension never clears selection to proceed.
Storage, schema, backup format and permissions are unchanged.

Version 3.8.3 reorders the popup by task relevance: tags, JSON backup, CSV report, cleanup,
then optional native refresh. No features, IDs, stored marks or formats are removed.
The new supplied Dijit HTML exposes an input.dijitOffScreen[type=button] with valueNode
attach point and onclick:_onClick attach event. When exactly one belongs to the same
.dijitButton, the module clicks that native input once, as the visible __onClick wrapper
normally forwards to it. Otherwise it clicks only the original visible span. Disabled
input/widget states still prevent clicks. It does not invoke page objects/private handlers.
Read-only status includes in-memory automatic-attempt and observed-completion counts for
this page session; they are not stored or transmitted externally and do not imply server
success. This triggering change needs confirmation in the institutional session.
